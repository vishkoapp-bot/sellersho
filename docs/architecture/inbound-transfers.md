# Inbound provenance checkpoint (INV-02)

This checkpoint implements booking, explicit dispatch, cumulative physical receipt and cancellation. Receipts create quarantine balances. [INV-04](inbound-qc-disposition.md) adds cumulative disposition without a second supplier debit, and the [INV-09 checkpoint](exact-inbound-putaway.md) adds isolated acceptance tasks and exact putaway into sellable bins. The obsolete fail-only QC operation remains closed. `InboundFullReceiptLifecycleEnabled` is still false because the retained downstream compatibility branches require integration; this is not completed INV-02/04/09 acceptance or a hardware capacity certification.

## Caller transaction contract

`reserveInboundTransferTx`, `dispatchInboundTransferTx`, `receiveInboundLineTx` and `cancelInboundTransferTx` use caller context/transaction only. Callers prehold the typed supplier, every product then every SKU, and the shipment/inbound work guard. `lockInboundShipmentTx` discovers immutable provenance, acquires that prefix through CORE-01, then locks balances canonically. Booking's newly inserted header is protected by the preheld supplier/product/SKU guards and the same transaction. Provenance rows are subordinate metadata serialized by the existing work guard, not independent locks acquired after balances. No external provider work occurs in these transactions.

`InboundTransferLine` binds product/SKU, integer quantity, source kind, owned supplier origin, destination and external evidence. Empty SKU is supported only for an exact legacy product balance; NULL-variant history is never spread across SKUs. `InventoryOrigin` is the shared transfer origin value. Existing order capture interfaces and immutable financial origins are unchanged.

Booking transfers exact matching supplier sellable balance quantities into `inbound_reserved`, retaining immutable original balance IDs and allocation quantities. A shortage fails the entire header/line/reservation transaction. Dispatch moves these reservations into transit once. Receipt accepts cumulative quantities monotonically up to dispatched quantity and moves only the delta to quarantine at `inbound-line:<line-id>`. Cumulative 2 then 5 of 5 credits 5 total; retry 5 adds zero; 6 fails. The line identity is unique independently of request keys. Supplier creation keys still bind the complete canonical contents and now source evidence too.

Undispatched cancellation restores the exact source allocation IDs once. Dispatched units never return sellable through cancellation. Replayed dispatch preserves the current received status. External replenishment is a separate, single-line carton mode requiring a unique external reference and reason; it reserves no existing units, credits only its verified received delta, and cannot also carry a transfer source or reuse the reference under another key/quantity. Warehouse receipt routes retain existing staff authorization. Both ASN and carton UI expose source/destination; carton UI exposes external evidence and explicit dispatch/cancel actions. Carton actions use the existing authenticated POST shipment route with `action` and `shipment_id`.

## Migration and history

`202611140006_inventory_transfer_provenance` is additive. It adds no historic source debit, receipt or SKU allocation. Its immutable identity trigger rejects source/destination/quantity/allocation changes and regressing counters. The external reference has database uniqueness. Rollback refuses any persisted provenance and cannot restore the old shipment constraint while additive live states exist.

Run `scripts/inbound-transfer-preflight.sql` on an explicitly selected review database. Its read-only transaction classifies unreserved draft/transit and previously received shipments in `inbound_transfer_reconciliation`. Every unresolved row requires evidence, actor and counted reconciliation in the existing administrative audit process before any manual repair. Never infer old sources from current product origins, synthesize anonymous stock or debit twice. An exactly matching historical receipt with positive persisted accounted quantity can be acknowledged without writes; changed or unknown history fails closed.
