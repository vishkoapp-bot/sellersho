# Route actions 04: supplier panel and supplier administration

Scope: exact `mux.HandleFunc` registrations starting at `backend/cmd/server/main.go:1614–2140` inclusive. The last registration starts on line 2140; its closure is read through line 2142. Sub-actions are relative to their registered prefix, not separate registrations. Source filenames in the table are relative to `backend/cmd/server/`.

**S** means `RequireSupplierAccess`: `RequireRoles` delegates to capability middleware (not a raw role comparison), with `supplier` and `admin` accepted and `admin` expanding to include `super_admin`. The direct `admin` capability branch skips the supplier permission, path ownership check, and supplier-context injection. Otherwise, `supplierAccess` normally resolves active owner/member access and requires the path permission listed below or `supplier.manage`; it tests activity, not approval status independently. Its separate `HasCapability("admin")` branch takes `supplierId` from the query. Handlers using `getSupplierIDFromContext` use injected scope if present, otherwise look up a supplier by the caller's user ID; the direct-admin bypass is not a blanket supplier impersonation mechanism. **A** means `RequireRoles("admin")`, including `super_admin`, without the supplier tenancy wrapper. See `auth_handlers.go:108–155`, `supplier_team_handlers.go:15–110`, `supplier_handlers.go:128–139`, and `backend/internal/auth/jwt.go`.

The supplier wrapper's `OwnsSupplierResource` checks the **first** segment under selected prefixes (product, inbound, campaign, discrepancy in this slice), with empty/reserved-segment exemptions and an exact implicit-agreements exemption. Other prefixes pass this stage. It does not authorize nested or body IDs by itself. See `backend/internal/repository/supplier_repo.go:288–323`. Method checks may be in dispatch or in the destination handler.
